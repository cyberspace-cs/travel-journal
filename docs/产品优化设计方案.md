# 旅行手帐 AI 产品优化设计方案

## 一、产品定位

**Slogan**：旅行的声音，我帮你留着

**核心差异化**：白天你玩你的，晚上手帐自己长出来

**目标用户**：
- 喜欢旅行、爱记录的年轻人（20-35 岁）
- 喜欢小红书风格、松弛感生活方式的用户
- 想记录旅行但懒得写日记的人

---

## 二、内容类型路由设计

### 2.1 三种内容模式

| 模式 | 适用场景 | 输出风格 | 金句分类 |
|---|---|---|---|
| ✈️ 旅行手帐 | 旅行见闻、风景、美食、感受 | 松弛感、小红书风、emoji、个人感受 | 旅行金句 155 句 |
| 📋 工作摘要 | 会议、工作讨论、汇报 | 结构化、要点清晰、分点列出 | 工作金句 74 句 |
| 📔 日常日记 | 生活琐事、心情、日常 | 温暖、治愈、小确幸 | 日常金句 120 句 |

### 2.2 智能路由逻辑

```
用户上传录音
    ↓
ASR 转写 → 文本
    ↓
内容分类 Agent（规则化，不调大模型）
    ↓
┌─────────┬─────────┬─────────┐
│ 旅行内容 │ 工作内容 │ 日常内容 │
│ score≥2 │ score≥1 │ 其他    │
└─────────┴─────────┴─────────┘
    ↓         ↓         ↓
旅行手帐   工作摘要   日常日记
pipeline   pipeline   pipeline
    ↓         ↓         ↓
提示用户   提示用户   提示用户
可切换模式  可切换模式  可切换模式
```

### 2.3 用户体验流程

1. 用户上传录音
2. 系统自动识别内容类型
3. 展示识别结果和提示
4. 用户可以选择：
   - 确认当前模式
   - 切换为其他模式
5. 生成对应风格的内容

## 三、旅行手帐优化设计

### 3.1 写作风格要求（no-ai-slop 规则）

**禁用词**：
- 深刻、赋能、助力、打造、构建、砥砺、践行、赓续、擘画、绘就
- 非常好、特别棒、超级治愈（空泛形容词）
- 总之、总而言之、最后（总结式结尾）

**写作要求**：
1. 语气像自己在写日记，口语化、随意、自然
2. 有手帐格式感：分点、分段、像翻页一样
3. 有细节感：把具体细节写进去（米线、三十年、风）
4. 短句子为主，不要长句，不要排比，不要煽情
5. 适当用 emoji，每段 1-2 个就够了
6. 不要鸡汤结尾，不要每段都升华
7. 不要对称句式（不是...而是...）

### 3.2 手帐结构设计

```
┌─────────────────────────────┐
│  ✨ 今日金句（金句库匹配）    │
├─────────────────────────────┤
│  📝 手帐标题（8-12字）       │
├─────────────────────────────┤
│  🍜 片段1：具体细节描写       │
│  🌊 片段2：具体细节描写       │
│  🎸 片段3：具体细节描写       │
│  👣 片段4：具体细节描写       │
├─────────────────────────────┤
│  📅 今日时间线               │
│  10:00 古城逛吃              │
│  14:00 洱海边吹风            │
│  19:00 小酒馆听歌            │
├─────────────────────────────┤
│  ⭐ AI 自评（5个维度）        │
└─────────────────────────────┘
```

### 3.3 金句库设计

| 分类 | 数量 | 匹配方式 |
|---|---|---|
| 旅行类 | 155 句 | 按关键词匹配（大理、洱海、风、海...） |
| 日常类 | 120 句 | 按关键词匹配（早饭、上班、咖啡...） |
| 美食类 | 75 句 | 按关键词匹配（米线、火锅、好吃...） |
| 情绪类 | 75 句 | 按情绪匹配（开心、难过、放松...） |
| 工作类 | 74 句 | 按关键词匹配（会议、项目、效率...） |
| **总计** | **499 句** | **规则化匹配，不调大模型** |

## 四、分层存储架构设计

| 层级 | 技术 | 用途 | 一致性 | 示例 |
|---|---|---|---|---|
| ⚡ L1 内存缓存 | Python dict / 本地变量 | 金句库、规则表、热点数据 | 强一致 | 金句库、标签规则、情绪关键词 |
| 🗄️ L2 SQLite + SQLAlchemy | SQLite | 用户数据、手帐记录、反馈、标签 | 强一致 | 手帐表、用户表、反馈表、trace 表 |
| 🔮 L3 Chroma（本地） | Chroma | 向量检索、相似片段推荐、知识库召回 | 最终一致 | 相似旅行片段推荐、金句相似度匹配 |
| 🚀 L4 Qdrant | 生产级向量库 | 高并发向量检索、大规模知识库 | 最终一致 | 产品化后替换 Chroma，支持高并发 |
| 🌌 L5 Milvus | 大规模向量 | 全量旅行知识库、大规模相似推荐 | 最终一致 | 十万级以上旅行知识库、小红书文案库 |

### 4.1 各层详细设计

**L1 内存缓存层**
- 金句库（499 句）
- 标签规则表
- 情绪关键词表
- 地点识别规则
- 热点数据缓存
- 一致性：强一致，重启后从 L2 加载

**L2 SQLite 持久化层**
- journeys 表：旅程信息
- journals 表：手帐记录
- clips 表：音频片段
- feedback 表：用户反馈
- traces 表：Agent trace 记录
- styles 表：风格库
- 一致性：强一致，ACID 事务

**L3 Chroma 向量层**
- 旅行片段向量库
- 金句向量库
- 相似片段推荐
- 知识库召回
- 一致性：最终一致，写入后异步更新

**L4 Qdrant 生产层**
- 高并发向量检索
- 多租户支持
- 水平扩展
- 一致性：最终一致

**L5 Milvus 大规模层**
- 十万级以上向量
- 全量小红书文案库
- 大规模相似推荐
- 一致性：最终一致

## 五、成本优化设计

### 5.1 大模型调用优化

| 步骤 | 原来 | 现在 | 节省 |
|---|---|---|---|
| 内容分类 | 调大模型 | 规则化判断 | 100% |
| 打标签打分 | 调大模型 | 规则化判断 | 100% |
| 金句生成 | 调大模型 | 金句库匹配 | 100% |
| 情绪识别 | 调大模型 | 规则化判断 | 100% |
| 写手帐 | 调大模型 | 调大模型 | 0% |
| 自我评估 | 调大模型 | 调大模型 | 0% |
| **总调用** | 5-6 次 | **2 次** | **~60%** |

### 5.2 成本对比

| 方案 | 每次成本 | 1000 次成本 |
|---|---|---|
| 原来（全调大模型） | ~0.002 元 | ~2 元 |
| 现在（规则化+大模型） | ~0.0008 元 | ~0.8 元 |
| **节省** | **~60%** | **~1.2 元** |

## 六、核心功能设计

### 6.1 录音豆 SDK 对接设计

**对接目标**：接入安克录音豆硬件，实现 24 小时持续录音

**技术方案**：
```
录音豆硬件
    ↓
蓝牙连接手机
    ↓
录音豆 SDK（iOS / Android）
    ↓
本地音频流（24h 持续）
    ↓
┌─────────┬─────────┐
│ 白天实时处理 │ 夜间离线整理 │
│ （流式 ASR） │ （批量 ASR） │
└─────────┴─────────┘
    ↓
上传处理后文本（原始音频不上传）
```

**对接流程**：
1. 用户手机通过蓝牙连接录音豆
2. 录音豆 SDK 实时获取音频流
3. 白天：流式 ASR，实时打标签、筛选片段
4. 晚上（12 点自动 / 手动触发）：批量整理，生成完整手帐
5. 原始音频只存本地，处理后文本加密上传云端

**隐私设计**：
- 原始音频：只存用户本地
- 处理后文本：加密上传云端
- 用户可随时删除所有数据

### 6.2 地图页设计

**功能**：旅行足迹地图，把去过的地方标记出来

**页面设计**：
```
┌─────────────────────────────┐
│  🗺️ 我的旅行足迹            │
├─────────────────────────────┤
│                             │
│      📍 大理 (5天)          │
│         📍 丽江 (3天)       │
│                             │
│         📍 成都 (2天)       │
│                             │
│  📍 重庆 (4天)              │
│                             │
├─────────────────────────────┤
│  总旅程：4个城市 / 14天     │
│  总片段：86条 / 320分钟     │
└─────────────────────────────┘
```

**功能点**：
1. 旅行足迹地图：标记去过的城市/景点
2. 时间线关联：每个地点关联当时的录音片段
3. 旅行统计：总天数、总片段数、总字数
4. 城市详情：点击城市看具体手帐
5. 照片关联：时间戳匹配，照片+语音联动

**技术方案**：
- 前端：Mapbox / 高德地图 JS SDK
- 后端：地点识别（规则化 + 大模型）
- 数据：journeys 表 + clips 表 + 地点字段

## 七、隐私设计

### 7.1 三层隐私结构

| 层级 | 存储位置 | 内容 | 保留时间 |
|---|---|---|---|
| 原始音频 | 用户本地 | 录音豆原始音频 | 用户删除为止 |
| 转写文本 | 云端（加密） | ASR 转写的文字 | 用户删除为止 |
| 处理后内容 | 云端 | 手帐、标签、金句 | 用户删除为止 |

### 7.2 隐私承诺
- 原始音频只存在用户本地，不上传云端
- 转写文本加密存储
- 用户可以随时删除所有数据
- 不会用于训练模型
- 不会分享给第三方
